# 评测方法与局限说明

> 本文回答一个问题：这个项目声称的能力，是怎么测出来的，以及哪些地方它其实不行。
> 所有数字都可以用文末命令复跑。

## 三层评测，三个口径

| 层 | 用例来源 | 测什么 | 当前成绩 |
|---|---|---|---|
| L1 系统测试 | 作者手写，10 个套件 | 代码是否自洽、边界是否崩 | **276 项全绿** |
| L2 口语评测 | `eval/cases_oral.json`，100 条手写 | 普通人口语 → 证型对不对 | **Top1 72%**，过度诊断 0/8 |
| L3 外部临床 | TCMEval-SDT 200 例真实医案 | 面对真实门诊记录能不能复现诊断 | 覆盖 48%，完全匹配 **8%** |

三层从易到难，成绩从高到低，这是正常的。任何只报 L2 不报 L3 的中医 AI 项目，数字都可以打个折。

## L2：口语评测集怎么建的

100 条用例分三组：

- `core`（82 条）：41 个证型各 2 条，用人话写，不照抄知识库术语
- `hard`（10 条）：容易混淆的证型对（风寒束表 vs 风寒束肺、肾阳虚 vs 肾阴虚）
- `vague`（8 条）：「浑身不得劲」「感觉身体被掏空」这类无指向输入

期望证型允许给多个（`expect` 是数组），因为临床上「咳嗽、痰黄稠、发热」既可能是风热犯肺也可能是痰热壅肺，硬要求唯一答案会让评测本身失真。

**过度诊断**单独统计：`vague` 组里被给出了「较高/中等」把握的，算过度诊断；只给「较低」并声明证据不足的，不算。

当前结果：8 条笼统输入，0 条被硬安证型。

### 已知问题：会过拟合

这 100 条是作者自己写的，改代码时能看见答案。用它做回归没问题，用它证明"准确率 72%"要小心——换一组外部用例，成绩大概率下降。

这正是下一步要解决的问题，不是可以糊过去的点。

## L3：为什么真实临床医案只有 8%

TCMEval-SDT 的 200 例 Train 数据，每条是一位真实门诊病人的主诉 + 标准证型（66 种国家标准证型之一）。

结果：能落到 41 个已知证型里的只有 96/200（48%），与标准答案完全一致的只有 13/200，补证型后 17/200（8%）。

原因不是脚本写错了：

1. **词表覆盖不足**。国家标准有 66 个证型，本项目只实现了 41 个；真实医案里大量是复合证型（「肝郁脾虚兼湿热」），单一证型的打分模型天然对不上。
2. **表述差异**。真实医案写「脘腹痞满、嗳气不舒、舌苔薄白」，规则引擎的词表里是「腹胀、嗳气、苔白」。归一化层能救一部分，救不了全部。
3. **没有推理能力**。医生会看"病程、诱因、体质、既往治疗反应"综合判断，规则引擎只看关键词命中。

结论很清楚：**这条路（关键词规则引擎）在复杂临床场景上到不了能用的水平**。要往上走只有两条：接 LLM 做结构化抽取，或者把证型体系扩到 66 个并引入复合证型组合。两条都超出当前项目的范围，所以项目把定位收在"日常不适的养生参考"，并在 README 里把 8% 明写出来。

## 为什么明写短板

因为这个项目最大的风险不是准确率低，是被人当成医疗产品用。一个 41 证型的规则引擎如果标榜"AI 辨证准确率 95%"，会有人拿它替代就医；写明"临床只有 8%，它不是医生"，反而是安全的一部分。

## 复跑

```bash
python run_tests.py                 # L1：276 项
python eval/run_eval.py --md --verbose   # L2：100 条口语，写 eval/RESULTS.md
python scripts/evaluate_tcmeval.py  # L3：TCMEval-SDT 200 例
python scripts/regress_slang.py     # 口语回归基线
```

环境要求：Python 3.10+。L3 需要 `data/Train_TCM_Data_v1.json`（仓库内已含）。

## 后续可以怎么提分（按性价比）

1. **扩外部用例**：找人（或让另一个模型）独立写 100 条不看答案的口语用例，做真正的 holdout。
2. **扩证型到 66**：对齐国家标准证型表，L3 覆盖率会直接上一个台阶。
3. **复合证型**：允许两个证型组合输出（主证 + 兼证），真实医案大多是复合的。
4. **接 LLM 只做结构化**：不让 LLM 判证型，只让它把自由文本抽成标准症状词——这样能保住可解释性和离线能力。
